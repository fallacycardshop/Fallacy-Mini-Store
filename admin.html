Where shoppers drop off, counted server-side (no Pro plan needed). The gaps between steps are the useful part: cart → checkout shows form friction, payment → purchase shows hesitation at PayNow.

Recent Orders

Every confirmed order is saved here the moment stock is decremented — independently of the notification email. If an email never arrives, the full order is still recoverable from this list.

Customer Spend

Lifetime spend per customer, counting paid orders only. This is what the loyalty tiers will be set from, so read the distribution before picking thresholds. Sorted by spend; tap a column to re-sort.

Spend is lifetime: each order's amount is banked permanently the moment it's marked paid, so totals are not limited to the most recent 1,000 stored orders. To seed history the first time, run “Rebuild from orders” once — it credits every order currently stored and is safe to run again (it never double-counts). The only unrecoverable gap is spend from before order backup began.

Shopfront Proof Figures

The headline numbers shoppers see when they tap the recent-sales ticker. Entered by hand because they cover the whole business — the auction channel as well as this store — which nothing here can measure. Confirmed store orders are added on top automatically, so the cards figure keeps climbing between updates. Whenever you re-enter the cards total it becomes the exact number shown — the running count resets, so nothing is double-counted.

Restocking

Look up any card to see how it has performed here: how many sold, how fast, at what price, and when it last moved. Search by name or Card ID when stock lands, to decide pricing and whether it’s worth listing again.

Sales History

An inventory audit: for every listing, how many sold against how many are still on the store. Sold + available should equal the CSV stock — anything that doesn’t balance is flagged, which is usually a packing or stock-entry error worth checking before it compounds.

The date filter narrows the sales shown; stock figures are always current, so leave it blank when auditing totals.

Order records start is the day order backup went live. Sales before it were counted but never stored, so those cards are marked pre-tracking rather than flagged as a mismatch. Stock reconciliation is unaffected — it uses the sold counter, not the order list.

Featured Section Heading

Headings for the two special rows on the store, plus the promo banner. Change them whenever you like — “New in!”, “Weekend picks”, and so on. Emoji work fine. Shoppers see changes within a minute; no redeploy needed.

Card Lookup & Auction Hiding

Look up any Card ID to check its price, stock and status, or pull it from the store during an auction. Paste one Card ID or a whole batch — separated by commas, spaces or new lines, so a column copied straight out of a spreadsheet works. You'll see every condition listed under each ID and how many are genuinely still available, then you can pull the whole batch for a set number of hours so they don't compete with your auctions. They come back automatically when the time is up — nothing to remember.

Reset Sold Counts

This clears the running "sold" tally for every card, so newly restocked quantities in your CSV will display exactly as entered. It does not touch anyone's in-progress checkout — active payment sessions expire on their own as normal.
